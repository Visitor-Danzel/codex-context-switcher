## 先了解清单方式

本工具使用官方 `model_catalog_json` 配置。它不仅提供各模型的上下文容量，**也会让 Codex 使用本工具的模型清单，取代原生在线模型发现**。这是本版本明确接受的工作方式，并非“原生列表完全不受影响”。此前错误的无影响承诺继续撤回。

清单在构建时通过已安装官方 CLI 的 `debug models --bundled` 取得；保留完整模型顺序和元数据，只修改勾选模型的 `context_window`。随附清单不等于账户实时可用列表，列出 Terra 等模型不代表账户已获得访问权限。默认值等于最大值的模型显示“已是最大”，不提供无效切换。

**新模型不会自动出现。** Codex 客户端更新后，本工具会拒绝使用旧版本资料保存新设置；重新运行构建脚本，读取新客户端的随附清单，再明确保存升级。仅服务器发布的新模型即使客户端版本未变，也可能尚不在随附清单中；当前版本不能自动发现或保证包含它们。需要原生实时发现时，请使用“恢复默认”。

## 构建和使用

需要 macOS 13+、Xcode Command Line Tools 和 Python 3.11+；当前测试平台为 macOS arm64，官方内置 CLI 0.165.0-alpha.1.2，应用位于 `/Applications/ChatGPT.app`。

```sh
sh scripts/build-context-repair-candidate.sh
open "build/legacy-context-repair-candidate/Codex Context Switcher.app"
```

1. 在工具中分别勾选需要最大上下文的模型，其余使用随附默认值。
2. 完全退出 Codex / ChatGPT 桌面客户端及官方 CLI，关闭配置编辑器。
3. 点击“保存”，阅读影响说明，确认退出及独占编辑条件。
4. 重新打开 Codex，使用新聊天，并从原生上下文圆环查看实际容量。

本版不保证下一条提示词会让已有聊天重新加载容量；以重启后的新聊天为验证路径。工具重启后会重新读取真实配置，不靠上次窗口的勾选猜测状态。已保存配置与聊天实际采用分开说明，工具不会自动读取聊天证明生效。

“恢复默认”移除本工具的清单覆盖，**同时取消本工具提供的容量设置**，重新交由 Codex 发现模型。“撤销上次保存”恢复之前的配置，可能恢复较旧清单；清单已修改或缺失时停止。正常升级保留仍可扩展模型的勾选；已移除或不再可扩展的旧选择会在界面及保存确认中明确列出，不会默默沿用。

## 保存保护与限制

只编辑用户 `~/.codex/config.toml` 的根级 `model_catalog_json`；生成的清单和事务备份在 `~/Library/Application Support/CodexContextSwitcher`。其他配置按原字节保留。本工具不修改或重签原生程序，不处理聊天数据库、认证文件、钥匙串、路由、额度或个人事务。配置工作进程禁止联网。

保存要求进程已退出、预览确认仍有效、客户端和来源身份未变化、配置未被外部改动。保留私有备份；中断后先检查结果，不自动回滚或覆盖。配置路径异常、未知第三方清单或其他容量配置冲突时停止。保存期间仍须避免其他程序同时编辑配置；工具不能阻止所有外部编辑者。

退出工具不会自动撤回设置。恢复默认、撤销和重建均不会自动执行。更新工具也不会替用户静默保存真实配置。

## 验证

```sh
sh scripts/test-maximum-context.sh
```

自动化测试使用指定隔离资料，详见 [验收范围](ACCEPTANCE.md)。2.3.0 已完成一轮真实使用验收：用户退出 Codex、保存选择并重开后，GPT‑6.1 Sol 与 GPT‑6 Luna 的原生上下文圆环均显示 828k，GPT‑6.1 Terra 已出现在模型列表中。只读回查确认两个模型均配置为 872000，保存记录一致；当前随附模型资料采用 95% 可用比例，872000 × 95% = 828400，与 828k 显示一致。配置由用户主动保存，验证过程未再次改写。该结果覆盖这次已选模型，不是所有模型的服务器满窗口压力测试或未来版本兼容保证。
